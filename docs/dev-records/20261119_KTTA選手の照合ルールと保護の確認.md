# KTTA 選手照合ルールと保護の確認

## 選手の照合

- 選手台帳の重複候補は、漢字一字違い、または氏名は同じでも所属クラブが異なる場合を確認待ちとする。氏名やクラブ一項目だけで同一人物と断定しない。候補の一覧は通常管理者が見られ、統合と取り消しはオーナーが行う。
- 選手登録台帳の取り込みは、疑義がある行を保留して既存の氏名・所属を上書きしない。通常の承認は選手台帳の候補を比較して行う。取り込み元にしか存在しない行を保留一覧から直接承認するボタンはこの変更に含まれない。
- 管理一覧と候補の比較に既存のランダム6桁の選手番号を使用し、番号で検索できるようにする。未付与の既存選手への一括発番は実施しない。内部の参照キーは変更しない。公開申込での自動照合は変更対象外とした。
- 将来の選手名簿は公開を目標とするが、自由閲覧／ログイン、対象選手、公開項目を決めるまでは現行の閉鎖を維持する。ログインを採る場合も、誰にどの選手を見せるかを別に定義する。

## セキュリティ点検

- 隔離テストで、オーナー権限の付与・解除と運営者の停止が担当コードで記録され、メールアドレスは監査記録に含まれないことを確認。権限を解除された利用者は通常運営権限に戻り、アカウント停止は既存のログインにも反映された。本番の権限・アカウントを変更していない。
- 本番でオーナー用の鍵が設定されていることだけを検査した。値と本番の監査記録の内容は取得していない。
- 架空のSQLiteバックアップを使い、復元、破損時の自動復旧、復元前の安全網を作れない場合の中止を確認。本番の最新バックアップは圧縮ファイルの整合確認を通過した。本番DBの復元操作は未実施で、同じバックアップの隔離環境への復元可否は未確認。
- 本番のバックアップログではサーバー外退避が未設定。同じサーバーを失う事態への備えとして、アクセスを限定した別の保管先と、隔離環境での復元訓練を先に決める。
