# 申込の選手照合（案A）と申込フォームの項目追加

2026-11-14 / ブランチ codex/entry-intake-integrity（未コミット時点の記録）

## オーナーの決定（11-14）

- 公開フォームには選手一覧も候補も出さない。申込を保存した後、サーバが選手DBと照らし合わせる
- 漢字とふりがなの両方が一致した人だけ、選手IDを自動で付ける。統合した書き間違い（別名）も同じ人として数える
- 1字違いなど怪しいものは管理画面で「要確認」にする。統合と確定は人が決める
- フォームで聞く項目: 姓・名、せい・めい、性別、学年（小1〜6・中1〜3・高1〜3・一般）、所属、支部、初めて出場する／出場したことがある
- 生年月日は聞かない。ダブルスは選手1・選手2のそれぞれに聞く

## 照合の判定

| 申込の内容 | 結果 |
|---|---|
| 漢字（旧字・空白を畳む）とふりがなが、登録の1人と一致 | 自動で一致（選手IDが付く） |
| 統合した書き間違いの表記で申し込まれ、ふりがなも一致 | 自動で一致 |
| 漢字は一致したが、読みが違う／登録に読みが無い／申込にふりがなが無い | 要確認 |
| 読みは一致したが漢字が違う、または1字違い | 要確認（候補を表示） |
| 該当なしで「初めて出場する」 | 新規候補 |
| 該当なしで「出場したことがある」 | 要確認（候補なし） |

- 照合に使うのは申込者が書いたふりがなだけ。苗字辞書で推測した読みは使わない
- 人が決めた結果（既存の選手に付ける・新しく登録・照合しない）は、照合をやり直しても変わらない
- 既存の選手に付けたとき、表記が違えば別名に残るので、次の大会からは自動で一致する。登録に読みが無ければ申込の読みで補う
- 新しく登録した人には6桁の選手番号（ランダム、使い回さない）が付く
- 選手を統合すると、消える側の氏名・別名が残る側の別名に引き継がれる。統合を取り消すと元に戻る
- 団体戦のメンバーは照合しない（従来どおり）

## 使い方（本部）

1. 大会の申込設定で「選手登録用の項目をまとめて必須にする」を押して保存する（既存の大会は従来の項目のまま）
2. 申込が来たら「選手の照合」を開き、「確認が必要」の人だけ判断する
   - 候補の中に本人がいれば、その行を押す
   - いなければ「新しい選手として登録」
3. 選手DBを直した後は「もう一度照合」で、まだ判断していない申込を照らし合わせ直せる

## 集計シート（GAS）

- 支部・出場経験の列は、フォームの項目設定から自動で追加される（form_schema の列追随）
- 今回の変更では GAS のコードを変えていないので、貼り替えは不要の見込み
- 本番の新しいフォームで1件送って、シートに支部・出場経験の列が出るかを確認する必要がある（未確認）

## 選手台帳の取り込み（本番はオーナーの確認後）

```
DB_PATH=<対象DB> node tools/import_player_registry.js data/選手登録/tools/registry.json          # 件数の確認だけ

```

ローカルDBの複製で試した結果（2026-11-14）:

- 台帳 1,144人 → 既存の選手と結び付け 381・新規 739・保留 24
- 保留の内訳: 同じ漢字で読みが違う選手がいる 23 / 同じ漢字の選手が複数 1（自動で結び付けない。人が判断）
- 2回目の実行は全件「取込済み」になり、重複して登録されない
- 台帳のふりがなは 1,144人中 631人ぶん。読みの無い人は、最初の申込では「要確認」になり、本部が付けた時点で読みが登録される
